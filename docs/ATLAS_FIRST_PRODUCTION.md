# Counterfactual Atlas: first independent production rollout

## Channel contract and production gates

- **Only Counterfactual Atlas** receives on-device draft-generation and private-render capacity during the first rollout. All 48 channel definitions and audit obligations remain intact; Felix and GOTZ are always creator-led.
- Daily Atlas goal is **one fully researched long-form episode and two Shorts**. This is three independent, genuinely useful what-if stories per UTC schedule day, not three exports from the same script or interchangeable template videos.
- Visual identity: physically explained counterfactuals; accurate numeric diagrams, carefully distinguished real measurements versus hypothetical models, original 2D/3D orbital/environmental storytelling. Avoid unqualified causal predictions, unsupported numbers, repetitive narration and generic subscription end cards.
- Source-led factual accuracy, source attribution, physical assumptions, animation composition, audio, full decode, checksum and thumbnail review are distinct gates. A locally generated model draft never approves itself.
- **Publishing is disabled until the exact media is approved**, the Studio OAuth record is mapped to the correct Atlas channel ID, and every YouTube video has an explicitly verified future schedule. An expired schedule must never publish immediately. Other 47 channels must not be enabled merely by an Atlas pilot.

## How to focus the Mac (no second scheduler)

Write exactly `Counterfactual Atlas` plus newline to the mode file `var/supervisor/focus_channel.txt` in the Engine repository. The installed 15-minute macOS supervisor reads it at each new cycle, passes `--only Counterfactual Atlas` to the grounded planner, and `--channel Counterfactual Atlas` to the private render worker. Its existing exclusive worker lock continues preventing parallel renders. The full 48-channel inventory still reports coverage honestly.

To resume all 48, delete this focus file. To change focus, write another exact registered channel name. Invalid names stop the cycle without running any model or renderer. Do not change the whole-network cadence to zero just to focus a pilot.

## First publication workflow

1. Verify Studio's **Atlas exact OAuth mapping**, scopes and sync through the scheduled authenticated readiness audit. A channel name/handle alone does not prove the actual Google destination ID.
2. Review the complete existing Atlas video candidates and their source claims. A checksum verifies technical bytes, not factual accuracy or engaging visuals.
3. Prepare a **new future-dated editorial spec** for each chosen upload. Changing `publishAt` changes the source digest, so a fresh reviewed render is required by the current exact-media release contract.
4. Use the existing owner approval tied to the new spec SHA-256, actual reviewed MP4/thumbnail hashes and source. Promote only the approved package. Keep scheduled uploads private until YouTube's scheduled `publishAt`, with the actual uploaded video ID and status recorded.
5. Measure public **first 3 seconds, average viewed %, retention, topic, sources, subscribers per view** and 7/28-day cohorts. Use actual feedback only, never invent views or subscriber improvement. Separate organic Shorts from long-form audience metrics.
6. When the full cycle succeeds and content remains distinct, enable Atlas-only automated publishing through a separate explicitly authorized account-specific switch, not global YouTube auto-publishing. Keep a fail-closed incident stop and a per-video audit trail.

## Evidence/limit

This file is a production runbook, not evidence that 3/day are published. The Mac stops if powered off, storage remains finite, and independent off-Mac uptime has not been verified. YouTube's YPP inauthentic-content policy prohibits mass-produced repetitive content even where each upload is original code; publishing cadence does not guarantee monetization.
