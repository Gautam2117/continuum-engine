# Content-addressed release approvals

No episode is authorised for release merely because an AI model, render job,
GitHub Action or generated critic marked it valid.

For a **human-reviewed** completed MP4, create a separate `approvals/<spec-id>.json`
file and commit it to `main` after watching the full video with sound, checking
on-screen numbers and sources, continuity, licensing, captions and channel fit.
Use the exact `sha256sum specs/<date>/<slug>.json` bytes and the exact
`review-<spec-id>-<sha256>` artifact name generated by `review_artifact()`.

Schema (example values are not approval and will not validate):

```json
{
  "id": "2026-11-17-example-s1",
  "decision": "approved",
  "specSha256": "<actual 64-hex SHA256 of spec file>",
  "reviewArtifact": "review-<same-id>-<same-sha256>",
  "reviewedAt": "2026-11-16T12:00:00Z",
  "reviewer": "owner",
  "notes": "A specific assessment of the observed video, narration, claims, source credits, rights and fit."
}
```

Approvals expire after 60 days; releases must be scheduled at least 30 minutes
later. A changed script invalidates the approval automatically. The review
artifact must still exist and have valid technical checksums. Never create an
approval automatically from a generation, evaluation or production job.

After a genuine owner approval, run `Promote approved review` in GitHub Actions
for the exact spec path. The workflow downloads the exact approved artifact and
reuses its video bytes, rather than re-rendering a different video. Prior
unapproved releases remain in quarantine from new Studio ingestion.
